# 2ch風スレッド式掲示板(PHP + SQLite / JavaScript不使用)

HTML と PHP のみで作られた、JavaScript を一切使用しないスレッド式掲示板です。
板トップでスレッドを一覧・新規作成し、各スレッド内でレス(返信)を付けていく、
いわゆる「2ch/5ch」風の掲示板になっています。
データベースには追加のミドルウェアが不要な SQLite (PDO) を使用しています。

## 2ch風の機能

- **スレッド一覧・新規スレッド作成**(板トップ = `index.php`)
- **レス(返信)投稿**、レス番号は各スレッド内で1から連番
- **名前欄+トリップ**: 「名前#トリップ鍵」と入力すると `名前 ◆xxxxxxxxxx` の形で
  同じ鍵を知っている人だけが同じトリップを再現できます
  (※ 元祖2chのDES-crypt方式ではなく、独自のHMAC-SHA256方式です)
- **メール欄 + sage**: メール欄に `sage` と入力すると、そのレスではスレッドが
  一覧の上位に上がりません(下げ進行)。空欄や `sage` 以外の入力は通常どおり上がります
- **`>>N` 自動アンカーリンク**: 本文中の `>>1` のような記法を、同じページ内の
  該当レスへのリンクに変換します(JavaScript不使用、`id`属性とフラグメントのみで実現)
- **削除用パスワード**: スレッド・レスそれぞれに投稿時のパスワードで本人削除が可能
- **管理画面**: スレッド単位・レス単位での強制削除が可能
- **閲覧パスワード / 投稿パスワード(管理画面からON/OFF自由)**: 管理画面の
  「閲覧・投稿パスワード設定」から、掲示板を見るためのパスワード・書き込むための
  パスワードをそれぞれ個別に有効/無効化・変更できます(詳細は下記)

## 動作要件

- PHP 8.1 以上(`pdo_sqlite`, `mbstring` 拡張が必要)
- Apache または PHP 内蔵サーバーなど、PHP を実行できる Web サーバー

Ubuntu/Debian系での例:
```bash
sudo apt-get install php-cli php-sqlite3 php-mbstring
```

## ローカルでの動作確認

```bash
cd bbs
php -S 127.0.0.1:8000
```
ブラウザで `http://127.0.0.1:8000/` を開いてください。

## 本番環境へ設置する前に、必ず変更してください

`config.php` 内の以下の値は必ず変更してください(初期値のままでは危険です)。

1. **`BBS_SECRET_KEY`**
   CSRF以外の署名(Bot対策トークン・IPハッシュ化)に使う秘密鍵です。
   ```bash
   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
   ```
   で生成した値に差し替えてください。

2. **`BBS_ADMIN_PASSWORD_HASH`**
   管理画面(`/admin/`)のログインパスワードです。初期値は `changeme123` のハッシュです。
   ```bash
   php -r "echo password_hash('お好きなパスワード', PASSWORD_DEFAULT), PHP_EOL;"
   ```
   で生成した値に差し替えてください。

3. 可能であれば `config.php` と `data/` ディレクトリを公開ドキュメントルートの外側に配置してください。

4. 本番環境では必ず **HTTPS** を使用してください(Cookieのsecure属性やHSTSヘッダーが有効になります)。

## 閲覧パスワード / 投稿パスワードについて

管理画面(`admin/index.php` → 「閲覧・投稿パスワード設定」、`admin/settings.php`)から、
以下の2種類のパスワードを**それぞれ個別に**ON/OFFできます。

- **閲覧パスワード**: 有効にすると、管理者以外は掲示板を見る前に `gate.php` で
  パスワード入力が必要になります。一度正しく入力すればセッション内は再入力不要です。
- **投稿パスワード**: 有効にすると、スレッド作成・レス投稿のたびに(実際には
  そのセッションで最初の1回だけ)専用のパスワード入力が必要になります。

いずれも:
- パスワードは `password_hash()`(bcrypt)でハッシュ化してDBに保存されます。
- **管理者は常にどちらのパスワードもバイパスできます**(自分の掲示板から締め出されないため)。
- パスワードを変更すると、そのパスワードで解除済みだった既存セッションは
  自動的に再ロックされます(セッションに保持しているのはパスワードそのものではなく、
  「解除時点のハッシュ値」で、現在の設定ハッシュと一致しなくなるため)。
- 有効化する際にパスワードが未設定だと、安全側に倒して「誰も通過できない」
  状態になります(設定画面がその旨を警告します)。
- 閲覧パスワード入力(`gate.php`)には、管理者ログインと同様のブルートフォース対策
  (一定回数失敗するとIPごとに一時ロック)が入っています。

## ディレクトリ構成

```
bbs/
├─ index.php          … 板トップ(スレッド一覧・新規スレッド作成)
├─ thread.php          … スレッド詳細(レス一覧・レス投稿)
├─ delete.php           … 投稿者本人によるスレッド/レス削除(削除用パスワード認証)
├─ gate.php              … 閲覧パスワード入力ページ(閲覧制限が有効な場合のみ使用)
├─ config.php             … 設定・秘密鍵・管理者パスワードハッシュ
├─ db.php                 … DB接続・テーブル初期化・スレッド/レス作成・設定値の読み書き(SQLite / PDO)
├─ lib.php                … 共通関数(セキュリティヘッダー、CSRF、トリップ、閲覧/投稿ゲート等)
├─ style.css              … スタイルシート(JavaScriptは使用していません)
├─ .htaccess              … Apache用の多層防御設定
├─ data/
│   ├─ bbs.sqlite3         … SQLiteデータベース(初回アクセス時に自動生成)
│   └─ .htaccess           … このディレクトリへの直接アクセスを禁止
└─ admin/
    ├─ login.php           … 管理者ログイン
    ├─ index.php            … 管理画面(スレッド一覧・スレッド削除)
    ├─ thread.php            … 管理画面(スレッド内の個別レス閲覧・削除)
    ├─ delete.php             … 管理者権限でのスレッド/レス削除
    ├─ settings.php           … 閲覧パスワード・投稿パスワードのON/OFF・変更
    └─ logout.php             … ログアウト
```

## データベース構成(概要)

- `threads` … スレッド本体(タイトル・1レス目=OPの内容・レス数・最終書き込み時刻など)
- `replies` … 2レス目以降の返信(スレッドへの外部キーは `ON DELETE CASCADE` で、
  スレッド削除時に配下のレスも自動的に削除されます)
- `post_log` / `admin_login_attempts` … 連投制限・ブルートフォース対策用のログ

## 実装しているセキュリティ対策

| 脅威 | 対策内容 |
|---|---|
| **SQLインジェクション** | 全SQLをPDOのプレースホルダで実行(`PDO::ATTR_EMULATE_PREPARES = false` でネイティブプリペアドステートメントを強制)。文字列連結によるSQL組み立ては一切行っていません。 |
| **XSS(クロスサイトスクリプティング)** | 出力箇所は必ず `htmlspecialchars()`(`h()`関数)を経由。改行表示も、エスケープ後の文字列に対してのみ `nl2br()` を適用。JavaScriptは1行も出力していません(`script-src 'none'` を含むCSPで多重に禁止)。 |
| **CSRF(クロスサイトリクエストフォージェリ)** | 全ての状態変更リクエスト(投稿・削除・ログイン)にセッション紐付けのCSRFトークンを要求し、`hash_equals()` でタイミングセーフに検証。成功後はトークンを再発行。 |
| **セッション固定攻撃・セッションハイジャック** | `session.cookie_httponly` / `cookie_samesite=Strict` / `use_strict_mode` を強制。管理者ログイン成功時に必ず `session_regenerate_id(true)` を実行。一定時間ごとにセッションIDを再発行。 |
| **クリックジャッキング** | `X-Frame-Options: DENY` と CSP の `frame-ancestors 'none'`。 |
| **MIMEスニッフィング** | `X-Content-Type-Options: nosniff`。 |
| **総当たり(ブルートフォース)攻撃** | 管理者ログイン・削除パスワードともに、一定時間内の失敗回数でロックする仕組みを実装。パスワード照合はすべて `password_verify()`(タイミングセーフ)。 |
| **スパム・フラッド投稿(Bot対策)** | ①ハニーポット欄(CSSで視覚的に隠したダミー入力欄。Botが入力すると投稿は静かに無視される)、②フォーム表示から一定秒数(既定3秒)未満での送信を拒否するHMAC署名付きタイムトークン、③同一IPからの連続投稿間隔・時間あたり投稿数を制限、の3段構え。 |
| **不正な入力・データ破損** | 文字数上限チェック、不正なUTF-8シーケンスの拒否、改行・タブ以外の制御文字の除去をすべてサーバー側で実施。 |
| **パスワードの平文保存** | 削除用パスワード・管理者パスワードともに `password_hash()`(bcrypt)でハッシュ化して保存。削除用パスワード未入力の投稿は、本人にも分からないランダム値でハッシュ化するため、実質的に管理者以外は削除できません。 |
| **個人情報(IPアドレス)の取り扱い** | 生のIPアドレスはDBに保存せず、秘密鍵付きHMACでハッシュ化した値のみをレート制限用に保存。 |
| **設定・DBファイルへの直接アクセス** | `.htaccess` で `config.php` / `db.php` / `lib.php` および `data/` ディレクトリへの直接アクセスを拒否(Apache環境向け、多層防御)。 |
| **ページネーション等のパラメータ改ざん** | `filter_input()` による整数検証、LIMIT/OFFSETは必ず `PDO::PARAM_INT` でバインド。 |
| **不正なHTTPメソッドでの状態変更** | 投稿・削除・ログイン処理はPOSTメソッドのみ許可(GETでの実行は405を返す)。 |
| **情報漏えい(エラーメッセージ)** | 本番運用時は `display_errors` を必ずOffにし、詳細なエラーはログにのみ出力する設定にしてください(`.htaccess` でも多層防御として設定済み)。 |

## 運用上の注意・追加で行うことを推奨する対策

- **HTTPSの有効化**(Let's Encrypt等)。HTTP運用のままだとCookieの盗聴やセッションハイジャックのリスクが残ります。
- サーバーレベルでの **WAF** や **fail2ban** などによる追加の攻撃検知・遮断。
- 定期的な **PHP・OSのアップデート**。
- `data/bbs.sqlite3` の定期バックアップ。
- 本番公開前に、`config.php` の秘密鍵・管理者パスワードを必ず変更すること(上記参照)。
- 大規模運用する場合は SQLite ではなく MySQL/PostgreSQL への移行(`db.php` のPDO接続部分を差し替えるだけで対応可能な設計にしています)。
